# 门灯复核工具代码结构

[使用说明](../README.md) · [Windows 启动入口](../启动复核.cmd)

```text
项目根目录/
├─ web/复核.html               页面、样式与原生 JavaScript
├─ web/server.py              HTTP 接口、索引缓存与标注写入
├─ 启动复核.cmd                Windows 启动入口
├─ demo.py                    合成演示图与对应标注
├─ tests/test_review.py       临时数据的 HTTP 集成测试
├─ docs/screenshots/          合成演示的实际网页截图
├─ data/图像/                  本机图片与同名 JSON（Git 忽略）
└─ .venv/                     本机 Python 虚拟环境（Git 忽略）
```

服务脚本默认读取 `data/图像`，只监听 `127.0.0.1:8768`。可指定其他图片目录与端口。在浏览器刷新即可加载更新后的 HTML，更改 Python 代码后需要重启服务。数据交换以图片旁同名 JSON 为准。

## 前端：复核.html

| 要调整的功能 | 代码入口 | 当前实现 |
| --- | --- | --- |
| 筛选、分页、图片卡片 | `render()`、`createCard()`、`makePreview()` | 在浏览器按门、灯、验收状态和编号或文件名筛选目录索引。默认每页 50 张，可设 1–150 张；只渲染当页并懒加载图片。 |
| 多选和批量操作 | `updateSelection()`、`editStates()`、`saveChanges()` | 支持单选、Shift 连选、全选本页或筛选结果。改筛选清空勾选，翻页保留勾选。 |
| 单图选框和改分类 | `openDetail()`、`selectBox()`、`updateBoxControls()` | 图片上叠加 SVG。可按框编号选中；双击打开分类菜单。框显示顺序可变，保存按原 JSON 中的 `shapes` 索引定位。 |
| 新增、调整、删除框 | `renderBoxHandles()`、`previewBoxDrag()`、`finishBoxDrag()`、`viewer` 的指针事件 | 选择类别后拖出新增预览；现有框可拖 8 个控制点。用 SVG 的坐标变换将屏幕坐标转成原图坐标；等待确认后提交。按 `Delete` 显示删除确认。 |
| 重读和保存反馈 | `load()`、`saveChanges()` | 根据目录版本应用变更项，成功后更新列表和当前单图。筛选、分页和显示设置可存到浏览器的 `localStorage`。 |

当前五类：门是 `door_open`、`door_closed`；灯是 `light_on`、`light_off`、`light_unknown`。

## 后端：server.py

| 路由 | 用途 |
| --- | --- |
| `GET /` | 读取并返回当前 `复核.html`。 |
| `GET /api/catalog` | 返回图片名、验收状态、图像尺寸、框列表和标注版本。带 `since` 时尽量只回传新增、变化与删除项。 |
| `GET /image/<文件名>` | 从图片目录读取原图。 |
| `POST /api/approve` | 给所选未验收图片写入 `checked: true`。 |
| `POST /api/relabel` | 批量改门或灯的分类。门要求每图恰好有一个门框；灯支持左、右、全部，左或右要求每图恰好两个且可区分左右。 |
| `POST /api/box-edit` | 单图单框操作，支持 `add`、`resize`、`relabel`、`delete`。 |

- `read_annotation()` 把 `shapes[].points` 转成页面用的 `[左, 上, 右, 下]`，并把原 JSON 的 SHA-256 作为 `revision`。`Catalog.scan()` 每次重读仍检查目录，用文件元数据判断哪些 JSON 需要重新解析。
- `relabel_boxes()` 和 `edit_box()` 分别处理批量分类和单框变更。新增以常见的矩形两点格式追加，`group_id` 默认为空；调框保留原有两点或四点格式和顺序。
- `save_annotations()` 汇总所有写入：复查 `revision`，备份原 JSON，写同目录临时文件，再用 `os.replace()` 整个替换。保存前又比对了一次磁盘内容，以降低与桌面软件同时保存时覆盖修改的风险。网页不会写入像素文件，也不会因新增、改框、改分类或删除而改变 `checked`。

## 两种同步方向

1. **X-AnyLabeling → 网页**：软件保存后点网页「重读标注」，网页同步磁盘上的变化。若版本已失效或服务重启，接口返回全量索引。这个过程不会重新推理模型。
2. **网页 → X-AnyLabeling**：在网页确认后写回同一 JSON。软件若已打开那张图，应重新载入它，再继续编辑，以免软件保存旧的内存副本。
